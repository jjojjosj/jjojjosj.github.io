## ✨ 핵심 변경 사항 요약

### 1. **PEP 810: 명시적 지연 import (Lazy Imports)**

- `lazy` 키워드를 사용하여 모듈을 지연 로드할 수 있습니다.

```python
lazy import json          # 첫 사용 시에만 로딩
lazy from pathlib import Path
```

- 큰 애플리케이션의 시작 시간을 획기적으로 단축합니다.
- `-X lazy_imports` 명령줄 옵션이나 `PYTHON_LAZY_IMPORTS` 환경변수로 전역 설정 가능

### 2. **PEP 814: `frozendict` 빌트인 타입 추가**

- 불변(immutable) 딕셔너리 타입이 새로 추가되었습니다. `dict`을 상속받지 않고 별도 타입으로 구현되었습니다.

```python
>>> a = frozendict(x=1, y=2)
>>> a['z'] = 3  # TypeError 발생!
```

- 해시 가능(hashing)하며, 키와 값이 모두 해시 가능하면 객체 자체도 해시 가능

### 3. **PEP 661: `sentinel` 빌트인 타입 추가**

- `builtins` 모듈에 `sentinel` 타입이 추가되어, 간결한 표현을 가진 고유 센티널 값을 만들 수 있습니다.

```python
>>> MISSING = sentinel('MISSING')
>>> MISSING
MISSING

def read_value(default=MISSING):
    ...
```

- **생성자**: `sentinel(name, /, repr=None)` — `name`은 필수 위치 전용 문자열 인자, `repr`은 선택적 키워드 전용 인자로 표현 방식을 커스터마이징할 수 있음
- **identity 보존**: `copy.copy()` / `copy.deepcopy()`를 해도 동일한 객체가 반환됨
- **pickle 지원**: 모듈 내에서 이름으로 import 가능한 센티널만 pickle 가능 (`pickle.loads(pickle.dumps(MISSING)) is MISSING`)
- **타입 표현식에서 `|` 연산자 사용 가능**: `__or__`/`__ror__`를 구현해 `int | MISSING`처럼 유니언 타입으로 사용 가능하며, 타입 체커의 타입 좁히기(narrowing)도 지원됨

```python
def foo(value: int | MISSING = MISSING) -> int:
    ...
```

### 4. **PEP 799: 전용 프로파일링 패키지 (`profiling`)**

- 새로운 `profiling` 패키지가 표준 라이브러리에 추가됨
  - `profiling.tracing`: 기존 `cProfile`에 해당
  - `profiling.sampling`: 신규 통계 샘플링 프로파일러 **Tachyon**
- **Tachyon**: 고속 통계 샘플링 프로파일러 (최대 1,000,000 Hz)
  - 실행 중인 프로세스에 attach 가능
  - 코드 수정 없이 성능 분석 가능
  - `wall`, `cpu`, `gil`, `exception` 등 다양한 측정 모드
  - pstats, collapsed, flamegraph, gecko, heatmap, 실시간 TUI 등 다양한 출력 형식 지원

### 5. **PEP 831: 프레임 포인터 기본 활성화**

- 시스템 레벨 관찰성(observability)을 위해 프레임 포인터가 기본적으로 켜짐

### 6. **PEP 798: 컴프리헨션에서 언패킹**

- 리스트/셋/딕트 컴프리헨션과 제너레이터 표현식에서 `*`, `**` 언패킹이 허용됩니다. 중첩 컴프리헨션이나 `itertools.chain` 없이도 여러 iterable을 하나로 평탄화(flatten)할 수 있습니다.

```python
>>> lists = [[1, 2], [3, 4], [5]]
>>> [*L for L in lists]  # [x for L in lists for x in L] 와 동일
[1, 2, 3, 4, 5]

>>> sets = [{1, 2}, {2, 3}, {3, 4}]
>>> {*s for s in sets}  # {x for s in sets for x in s} 와 동일
{1, 2, 3, 4}

>>> dicts = [{'a': 1}, {'b': 2}, {'a': 3}]
>>> {**d for d in dicts}  # {k: v for d in dicts for k, v in d.items()} 와 동일
{'a': 3, 'b': 2}
```

- 제너레이터 표현식(`(*L for L in lists)`)과 비동기 제너레이터 표현식(`(*a async for a in agen())`)에서도 동일하게 사용 가능합니다.

### 7. **PEP 686: UTF-8 기본 인코딩**

- Python이 시스템 환경설정과 무관하게 기본적으로 UTF-8 인코딩을 사용하도록 변경
- `PYTHONUTF8=0` 또는 `-X utf8=0`으로 비활성화 가능

### 8. **타입 시스템 개선**

- **PEP 728**: `TypedDict`에 타입화된 추가 항목 지원
- **PEP 747**: `TypeForm`으로 타입 폼 주석 지원
- **PEP 800**: 타입 시스템에서 분리된 기반 클래스(disjoint bases) 지원

### 9. **JIT 컴파일러 대폭 업그레이드**

- **성능**: pyperformance 벤치마크 기준 x86-64 Linux에서 표준 인터프리터 대비 **8~9% 성능 향상**(geometric mean), AArch64 macOS에서는 tail-calling 인터프리터 대비 **12~13% 향상** (아직 최종 수치는 아님)
- **LLVM 21 빌드 의존성**: 스텐실(stencil) 생성에 LLVM 21 사용 (빌드 시에만 필요, 최종 사용자는 LLVM 불필요)
- **새로운 트레이싱 프론트엔드**: 실제 실행 경로를 기록하는 방식으로 전면 개편되어, 더 다양한 바이트코드/제어 흐름을 이해함 (객체 생성, 오버로딩 연산, 제너레이터 일부 지원 등)
- **기본 레지스터 할당(register allocation)** 추가: 스택 연산 대신 레지스터를 활용해 더 효율적인 트레이스 생성
- **추가 최적화**: 상수 전파(constant propagation) 강화, 안전한 경우 참조 카운트(refcount) 갱신 생략, 고유 참조 추적을 통한 int/float in-place 연산 지원 등
- **디버깅 지원**: Linux ELF 플랫폼에서 GDB 및 GNU `backtrace()`가 JIT로 생성된 코드도 스택 언와인딩 가능
- **머신 코드 생성 개선**: x86-64/AArch64(macOS, Linux)에서 더 낮은 메모리 사용량과 효율적인 머신 코드 생성

### 10. **기타 개선 사항**

- 더 나은 에러 메시지
- 더 많은 컬러 출력 지원
- Windows 64비트 공식 바이너리에서 tail-calling 인터프리터 사용
- **PEP 803**: free-threaded 빌드의 안정 ABI(`abi3t`) 지원
- **PEP 788**: C API에서 인터프리터 최종화(finalization) 방지 보호 (interpreter guards, attach/detach API 등)
